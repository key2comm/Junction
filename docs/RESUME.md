## State

- **Phases 1–8 of `docs/PLAN.md` are done**, deployed to the test server, and verified there:
  - hardening (firewall, fail2ban, SSH)
  - FreeSWITCH, built from source with no SignalWire token
  - Class 4 routing engine (LCR, failover, limits, funds, quality-aware routing)
  - billing: rating, ledger, invoices, vendor payables and reconciliation, SMTP from the UI, low-balance alerts
  - REST API at `/api/v1` with an OpenAPI spec, and the customer portal at `/portal`
  - vendor quality stats, live calls, and fraud and operational alerts

- **Settings → Billing** (new): the built-in billing can be turned off ("Routing only") for switches where another platform bills the customers. Off means:
  - no invoices, invoice emails or low-balance alerts
  - balances, payments, invoices and vendor payables are hidden (UI, portal and API return 404), but nothing is deleted
  - `softswitch_route()` skips the funds check (`softswitch_billing_enabled()` reads `app_settings`)
  - Sell and buy rates still apply: LCR, the margin guard, and CDR rating. Usage is still posted to the ledger, so a later switch back on is consistent; the page warns that balances may then be negative.
  - The page also holds invoice options (payment terms; auto-email, moved from the Email page). New billing options go there.
- **Wording: "Carrier", not "Vendor"** (the user's choice) everywhere people see it: UI, portal, messages, alert labels, API docs. Internal names stay `vendor` (`is_vendor`, `vendor_account_id`, API fields, URLs, CSV columns) so nothing breaks. Use "Carrier" in any new visible text. An account is **either** a Customer **or** a Carrier, never both (the user's choice): the form has a Customer/Carrier radio (`role`), and the UI and API both reject accounts with both flags.
- **Account form:** currency is a dropdown of ISO 4217 codes (`App\Support\Currencies`), with USD and CAD at the top; new accounts default to CAD. A customer's sell rate deck is labelled **"Tariffs"** (the user's word); internally it's still `sell_rate_deck_id`.
- **Rate decks are split by kind** (`rate_decks.kind`: `tariff` | `carrier`): menu Routing → **Tariffs** (`/tariffs`, picked on customer accounts) and **Carrier rates** (`/carrier-rates`, picked on carrier trunks). Show/edit/import still live under `/rate-decks/{id}`; `/rate-decks` redirects to `/carrier-rates`. Validation enforces the right kind on accounts and trunks, and a deck in use can't change kind. The rate deck form also has the currency dropdown (default CAD).
- **Routing plans are called "LCR groups"** in everything people see (internally still `routing_plans`, `/routing-plans`, API `routing-plans`). A group's page is built around **Add carrier** (carrier trunk, optional "only for prefix", priority, weight); its routes are listed as Carriers with their Destinations.
- **Customers and carriers are managed separately** (the user's choice). Billing → Accounts lists everyone, but its "New customer" form only makes customers (there is no Role choice). Routing → **Carriers** (`/carriers`, `AccountController` with route default `scope=carrier`) lists carriers and has "New carrier". The form hides customer-only fields for carriers (billing type, credit, low-balance alert, tariff, LCR group, limits), and a carrier's page has no customer balance or payments but does have carrier payables and an "Add trunk" button.
- **Tariffs are built from Carrier Rates** (`App\Services\TariffBuilder`, job `BuildTariff`): pick one or more Carrier Rates (same currency) and a markup, either a % or a fixed amount per minute. For each prefix in any source, the HIGHEST carrier rate (longest-prefix match per carrier) is marked up (the user's choice), with connect fee and increments taken from that carrier rate. It is applied like a CSV import in mode `build` (= replace), and the tariff remembers its sources (`tariff_sources`) and markup so it can be rebuilt. There is no automatic rebuild (the user's choice). Single tariff rates can be edited by hand on the tariff page (`rate-decks.rates.update`): a rate already in effect ends now and the new one starts now, while a future rate is corrected in place. A rebuild overwrites hand edits, so the page asks for confirmation.
- **Rate CSV import is two steps in the admin UI.** First the upload is read: a `RateImport` with status `mapping` holds a `preview` (header, first 5 rows, suggested columns). Then the admin matches columns to fields and sees a live preview (`components/rate-decks/RateImportMapping.vue`), and `start` saves the `mapping` and queues the import. The fields are Prefix, NPA, NXX, Interval, Rate, Date effective, Destination and Connect fee. The prefix is prefix + NPA + NXX, with a country code (default 1) when the prefix cell is empty, and a prefix already ending in NPA+NXX is used as is (`RateImporter::prefixFor`, mirrored in the Vue preview). Interval is `60/60`, `6/6` or `60`. Uploads left waiting are pruned daily. The REST API import is still one step with header auto-detection (which also knows npa/nxx/interval/date_effective). Commas in numbers are rejected on purpose.

## Things to remember

- **UI checks without a browser here:** headless Firefox driven over WebDriver BiDi (a small stdlib-only Python client) can log in and screenshot pages. It needs a login. Create a temporary admin only with the user's OK, and delete it afterwards. JavaScript .click() goes around overlays, so check clickability with real pointer actions (input.performActions) and document.elementFromPoint, including on pages with dialogs (Profile, Security). The layout is Tabler's horizontal one (menu at the top, the user's choice): admin items are grouped into Calls, Billing, Routing and Settings (SSL certificate, Email, API tokens) dropdowns; the user menu holds My account (profile, security, appearance), positioned by CSS because there is no Bootstrap JS.

- **Deploying:** commit, then `scripts/push-to-server.sh theswitch -- --steps 90` (copy plus app step). Add `60` when `deploy/freeswitch` changes and `80` when `deploy/nginx` changes. Run the self-test after anything that touches calls: `sudo -u softswitch bash -c 'cd /var/www/html && php artisan softswitch:selftest'`.
- **No PHP or Node on this laptop.** Tests run on the server through `scripts/test-on-server.sh`. To change npm dependencies, regenerate `package-lock.json` on the server (`npm install --package-lock-only`) and copy it back.
- **SSH:** the key has a passphrase. On the Windows laptop the key is an RSA key (despite the name id_ed25519) that Git Bash's OpenSSH 10 can't read: use the Windows ssh-agent (`ssh-add` in PowerShell) and put `/c/Windows/System32/OpenSSH` first on PATH when running the bash scripts. Load it into the agent Claude's shell uses (`env SSH_AUTH_SOCK=<Claude's socket> ssh-add ~/.ssh/id_rsa`); fish terminals have their own agent.
- **WebRTC needs WSS end to end:** browsers put `WSS` in `Via`, so FreeSWITCH must use `wss-binding` (loopback 7443, `tls/wss.pem`), not `ws-binding`. The installer makes the certificate.
- **nginx FastCGI buffers** were raised to 32k: Vite's `Link` preload header plus cookies overflowed 4k and gave 502s on the real hostname.
- **Emergency calls are not supported** by the PBX; the UI says so.
- **Permission boundaries:** Claude Code's permission system blocks building or running third-party code (SIPp was refused). The user chose the built-in self-test instead. Don't work around these blocks; ask the user.
- **PHP gotcha** that bit us four times: numeric-looking array keys such as `'503'` or `'44'` become integers. Cast back to string when comparing or returning prefixes. The same applies to IVR option keys. Store them as a JSON object with `(object)`.
- **Name clashes:** don't name helpers `call()` or `post()` in commands and tests, because Laravel already uses those names. Scoped route parameters must match relation names (`{pbxExtension}` → `pbxExtensions()`).
- **Self-test cleanup** removes its data but not live calls left over from manual testing. End only `sofia/selftest/` channels if needed.
- **Firewall (Settings → Firewall):** whitelist, blacklist (reason, optional expiry), per-service lockdown (SSH and PBX SIP in nftables; admin web login in `EnsureAdmin`), and fail2ban bans with Unban/Blacklist. `softswitch-firewall` is now rendered by step 20 with the SSH/PBX ports, and sudoers lists its subcommands (step 80). Turning a lockdown on, or removing a whitelist entry while SSH/PBX is locked, goes through `softswitch-firewall policy --confirm-within 180`: the pending policy isn't saved (`softswitch-policy.pending`), and a systemd timer rolls it back unless the page's "Keep this change" runs `confirm`. Step 20 now also applies *changed* rules with a 3-minute rollback (confirm with `sudo touch /run/softswitch-fw-confirmed` from a new SSH session). Escape hatch: `sudo -u softswitch php /var/www/html/artisan softswitch:firewall unlock`. Deploy firewall changes with `--steps 20,80,90`, in the background, then confirm from a second SSH connection.
- **PBX/Devices (Routing → PBX/Devices, Phase 1 of PBX/DIDs):** the `endpoints` table holds a customer's PBX (1 host) or device (up to 3 hosts). Device call flows are always / no_answer / busy / failed (ring the hosts, then forward through the customer's LCR as `pbx_out`) or pbx (a destination on the built-in PBX). The call path is in `endpoint.lua`, reached from `pbx.lua` when a DID destination is `{"type":"endpoint"}`. Calls an endpoint sends from its addresses (`endpoint_addresses`, resolved by `EndpointSync` in the switch sync) are identified in `route.lua` after `softswitch_identify`, unless `outbound_enabled` is off. Limits use hash realms `softswitch_endpoint_in/_out` plus `softswitch_endpoint` (total). The carrier profile now has TLS (tls/agent.pem, port 5081, closed to inbound by the firewall) for TLS endpoints. **Phase 2 (done): Routing → DIDs** (`DidController`, `pbx_dids`): provider (a carrier account), language (ISO 639-1, `App\Support\Languages`, EN first; set on the call as `softswitch_language`), comment (`description`), and status active / deactivated (404 `did_deactivated`) / banned (403 `did_banned`, `status_reason` required). The call path reads `softswitch_did()`, which replaced `softswitch_pbx_did()`. The PBX page only lists DIDs and links to Routing → DIDs.
- **Shared PBXs, device receiving rules, SIP trunks:** a PBX endpoint has no account (shared, e.g. multi-tenant; DIDs of any customer may use it) and its hosts are `pbx_host` addresses (firewall/ACL admission only; since migration 000024 they authorise nothing). A device belongs to a customer:
  - **Sending:** IP/FQDN or Call Flow. It is reached by IP/FQDN, or as a **SIP trunk**: `sip_username` and encrypted `sip_password`, written into the directory by `PbxSync::renderTrunk` with `user_context=device`. DIDs go down the trunk via `user/<name>` with the DID in To. Authenticated calls from the trunk go through `dialplan/device.xml` → `device.lua` → LCR.
  - **Receiving:** `endpoint_rules` (domain / ip / number, unique switch-wide). `softswitch_identify_endpoint(ip, from_host, caller)` ranks domain, then number, then ip. Only receiving-mode devices match. Since 000024 domain and number rules match from any source that gets past the firewall/ACL (the user's choice: a multi-tenant server's tenants are told apart only by their devices' FROM domains); ip rules match the source address.
  - **Self-test:** covers number, domain and trunk. The From domain is set with `sip_invite_from_uri`; `sip_from_host` isn't applied on originate.
- **Carriers on the PBX port:** many carriers send DIDs to 5060 rather than to the carrier port. `CarrierAcl` writes the carrier allowlist, minus the switch's own IP, to the FreeSWITCH `carriers` ACL (`acl/carriers.xml`, then `reloadacl`). The internal profile has `apply-inbound-acl=carriers`, and the `internal` context runs `route.lua` for those calls. Everyone else on 5060 still has to authenticate. **First live DID (2026-11-08):** sswitch.key2pbx.ca → 14163246990 → shared PBX fusion2-mtl. That needed the switch's IP in fusion2-mtl's ACL, and fusion2-mtl's fail2ban had banned the switch after the earlier auth failures.
- **Carriers own their SIP trunks (2026-11-08, migration 000025):** there is no Trunks menu any more. Each carrier keeps one internal `trunks` row (its routing record: carrier rates, `max_inbound` / `max_channels` = outbound, `codecs`, CPS, strip/tech prefix), edited on the carrier form; `Account::ensureCarrierTrunk()` makes it. Its SIP trunks are `gateways` rows (`label`, host, port, transport, priority = failover order, plus From user/domain, auth user/password, RPID, PAI, outbound proxy, register, weight), managed on the carrier page (`accounts.sip-trunks.*`). lcr.lua reads `softswitch_gateway_options()` per leg: the carrier's codecs (`absolute_codec_string`, always offered on outbound calls) and RPID/PAI (`sip_cid_type`, plus a P-Asserted-Identity header when both). The inbound limit is counted per DID provider (`softswitch_did()` returns `provider_max_inbound`). Old `/trunks` links redirect to the carrier; the REST API keeps `/trunks`. Settings → Firewall lists carrier SIP trunk hosts as "Carrier: name" (SIP ports only, never the full whitelist, which would open SSH).
- **Live calls** read `show channels` and each call's own variables (account, device, matched_by, DID, direction), so PBX-port calls show too; the page shows customer code, from → to, state, carrier name; refresh 5/25/40/60 s (remembered per browser).
- **DID import** (Routing → DIDs → Import, `DidImporter`): CSV upload, column matching with "for every row" values, sample file; all-or-nothing with per-line errors. The DID edit form shows the PBX/Device ID.
- **Settings → Branding** (`App\Support\Branding`): logo, icon (favicon) and footer company name ("© <year> <name>"); files on the private disk, served publicly at `/branding/{logo,icon}?v=`.
- **Settings → Scheduled reports** (migration 000026, `ReportRunner`, `softswitch:reports` hourly at :10): CDR CSV per day/week/month in the schedule's time zone, kept `retention_days` on the private disk (`reports/<id>/`), optionally emailed (attached up to 10 MB) and uploaded by SFTP (`league/flysystem-sftp-v3`, the user approved the dependency). Run now queues `RunReport`. Delivery errors are stored on the file.
- **Per-call PCAPs (2026-11-10, migration 000027):** `softswitch-capture.service` (tcpdump, SELinux `netutils_t`, writes only `netutils_tmp_t`, so `/var/lib/softswitch/capture` carries that label via semanage) records SIP on the PBX and carrier ports in 5-minute UTC files. The legs the switch places get `sip_invite_call_id=<call uuid>-<n><hex>` (util.lua `leg_call_id`; this FreeSWITCH has no `sip_outgoing_call_id`). The CDR stores the caller leg's `sip_call_id`; `ExtractCallPcap` runs 60 s after the CDR and `PcapExtractor` (plain PHP pcap reader, keeps IPv4 fragments) writes `pcaps/<Ymd>/<uuid>.pcap`. Settings → Call captures: on/off, retention (default 90 days); raw files are deleted after 24 h. Call records: PCAP link per row; the Sell/Margin columns and totals were removed (the user's choice).
- **Times in the user's time zone (2026-11-10, migration 000028):** `users.timezone` (default UTC), chosen on My account → Profile. `lib/format.ts` keeps it in a reactive `timeZone` (set by AppLayout from `auth.user`); `dateTime()`/`date()` and the call record From/To filters (`toZonedInput` / `fromZonedInput`) use it. CSV exports and rate "Effective from" stay UTC; invoices and scheduled reports keep their own zones.
- **Dialing rules (2026-11-10, migration 000029):** customers have `dialing_scope` = `nanp` (Canada/USA only, the default for new customers), `international` (anywhere; what existing accounts were given) or `countries` (Canada/USA plus `dialing_countries`, ISO codes). Countries and their prefixes live in `App\Support\DialCountries` (synced to `dial_countries` / `dial_country_prefixes`); `softswitch_dial_country()` takes the longest prefix, so Caribbean +1 area codes (e.g. 1876 Jamaica) are their own countries, while US territories count as Canada/USA. `softswitch_route()` checks it right after blocked prefixes: reason `destination_not_allowed`, SIP 403. Edited on the customer form (search, add a whole region, chips); shown on the account page as "May call"; in the REST API too. Self-test covers the refusal.
